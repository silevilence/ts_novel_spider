# 精翻 Agent UI / UX 复查

日期：2026-10-27。触发：用户指出交付截图中底部导航文字截断，章节 Agent 悬浮按钮遮挡导航。此前“小屏操作可用”的验收判断不足，本记录替代该判断。

## Discover：从截图扩展到实际操作

依据用户反馈、代码审查和隔离浏览器中的实际操作；没有进行用户访谈，也不将代理走查称为用户可用性研究。

检查范围：全局导航及七个主页面的窄屏布局；精翻任务列表、新建、执行配置、运行状态、术语编辑、译文对照、章节聊天。预览使用内存 SQLite 和本地模拟模型，不读取用户书库，不调用真实 LLM。

## Define：问题与验收标准

用户需要在小屏上看清当前任务状态、切换页面并操作所选章节，不能因为导航拥挤、悬浮控件遮挡或状态表达错误而误操作。

验收标准：

- 320px 起主导航标签完整，导航可点击；业务按钮不得覆盖导航。
- 平板宽度不硬塞全部桌面导航；全部七个入口仍可访问。
- 精翻表单、标签页与术语操作无需整页横滑；矮窗口可滚动完成表单。
- 检查尚未返回时不能显示通过；历史证据不能冒充当前有效证据。
- 保存译名与确认术语分开；切章不得继承旧章对话或待确认提案。

## Develop：方案选择与修复

| 优先级 | 发现 | 实施 |
| --- | --- | --- |
| P1 | 七个底部入口挤成一行，文字截断 | 三个常用入口加“更多”，四等分；抽屉展示全部七个入口；平板改用菜单 |
| P1 | 章节 Agent 固定定位遮住底部导航 | 放入章节“浏览与定位”工具区，随正文滚动；导航保留独立底部空间 |
| P1 | 书库详情浮动翻页操作存在同类重叠风险 | 统一计入底部导航及安全区域偏移；控制台移动操作栏补安全区域 |
| P1 | 章节聊天标题跟随后台处理章，请求却使用用户选中章 | 标题统一使用所选章节；切章重置对话、草稿、段落上下文和提案；忽略跨切章迟到响应 |
| P1 | 译名失焦自动保存并确认术语 | 显式“保存译名”，保留原确认状态；失败保留草稿并就地显示错误 |
| P1 | 完成条件请求返回前，空数组被显示为检查通过 | 独立“正在检查”状态；请求失败展示失败提示；超过八项可展开全部 |
| P2 | 手机术语表宽 1050px，操作在屏幕外 | 窄屏改成带字段标签的卡片，页面纵向滚动；桌面保留表格与固定表头 |
| P2 | 抽屉透出底下文字，干扰导航阅读 | 抽屉与对话框使用不透明背景；关闭按钮增加可访问名称和触控区域 |
| P2 | 多重容器留白与双列表单压缩手机内容 | 减少详情外层留白、去掉重复标题；手机表单单列、四个标签页两列；收紧配置手风琴内边距 |
| P2 | 空聊天区固定占据 250px，使输入和发送挤出屏幕 | 空状态随内容高度，有对话时按屏幕使用有界消息区 |
| P2 | 运行/停止中的手工编辑入口状态不统一 | 禁用译文、术语及执行模型编辑；章节聊天限制只读；不可批准修改提案 |
| P2 | 已接受但未解决的审核意见从待处理列表消失 | 待处理按 resolved 判断；已解决意见才进入历史列表 |
| P2 | 图标按钮无名称、服务状态像无作用按钮、弱文本难读 | 补充可访问名称及当前导航标识；服务状态改为状态元素；提高暗色弱文本对比度 |

底部方案比较：保留七项但缩字会继续损害阅读和触控；横向滑动隐藏目的地且发现成本高；采用三项加“更多”兼顾常用入口与完整导航。章节 Agent 跟随章节定位区，避免用新的固定偏移继续叠加浮层。

### 尚未覆盖的边界

本轮是共享导航整体巡查与精翻主路径深入复查，并非全站所有业务组合的穷举验收。没有实机 iOS / Android 软键盘、安全区设备、屏幕阅读器或真实用户测试；安全区使用标准 CSS 环境变量，但浏览器模拟不能代替实机验证。模拟模型不证明真实模型质量，超长任务数据和大量审核意见的性能也未在本轮压测。
