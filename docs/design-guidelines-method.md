# Design Guidelines — 扫描与重构方法

> Phase 1 / Step 2 交付物。定义审查维度、证据采集格式、通过标准和常见修复动作。
> 本文件只定义"怎么审"，不给出审查结论。实际扫描按 Phase 1 / Step 3 的顺序执行。

---

## 1. 扫描维度

### 维度 A: 信息层级 (Information Hierarchy)

| 项目 | 内容 |
|------|------|
| **观察对象** | 页面标题 (h1/h2)、副文案 (hero-copy/route-copy)、摘要条 (summary-strip)、卡片标题 (h3/label)、正文内容 |
| **采集方式** | 逐页截图 + 标记层级编号。对每个可见文本块标注它是第几级信息。检查同一页面内是否有同级信息视觉权重不一致。 |
| **通过标准** | 用户扫读时能在 3 秒内定位: (1) 当前在哪 (2) 能做什么 (3) 关键数据是什么。字体大小、颜色、间距线性递减，无跳级。 |
| **常见修复动作** | 调整字号阶梯 (eyebrow → h2 → route-copy → label → body)；统一摘要卡片的信息密度；标题区与内容区之间保证可辨识的视觉分隔。 |

### 维度 B: 主次操作权重 (Action Hierarchy)

| 项目 | 内容 |
|------|------|
| **观察对象** | 页面内所有按钮/链接。按 primary > secondary > ghost > subtle > text-button 分级。 |
| **采集方式** | 统计每页每种按钮类型的数量。检查: 是否存在同一行内有多个 primary；是否存在真正的 primary 操作被降级为 ghost；danger 操作是否有确认步骤或足够间距。 |
| **通过标准** | 每屏 (viewport) 最多 1 个 primary 按钮；danger 操作不与 primary 相邻；同组操作的视觉权重一致。 |
| **常见修复动作** | 提升主操作至 primary-button；降级批量操作中次要项为 ghost；danger 操作加间距或用 ghost-button.danger；操作栏按权重从左到右排列。 |

### 维度 C: 空间利用率 (Space Efficiency)

| 项目 | 内容 |
|------|------|
| **观察对象** | 页面首屏 (above the fold) 的实际可用内容比例；大片留白区域；重复的标题结构；padding/margin 与内容比例。 |
| **采集方式** | 在 1440px 和 900px 宽度分别记录首屏可见的实际业务内容高度。标注哪些区域是纯装饰/重复说明/空白。计算首屏内容占比。 |
| **通过标准** | 首屏至少 60% 空间用于可操作内容或关键信息；无连续两行以上的纯说明文本未附带操作入口；空状态区域不占据主要视觉焦点。 |
| **常见修复动作** | 压缩 hero/shell-header 的 padding 和纵向 gap；合并重复的说明文字；将非核心信息移入折叠面板；摘要卡片从 4 列压缩或改为横向排列。 |

### 维度 D: 非核心信息折叠候选 (Collapse Candidates)

| 项目 | 内容 |
|------|------|
| **观察对象** | 所有页面区域，按"每次访问都需要" vs "偶尔需要" vs "几乎不需要" 三级分类。 |
| **采集方式** | 对每个页面区域标注使用频率预估 (高频/中频/低频)。高频区域不应折叠；中频区域可提供默认展开的折叠；低频区域默认折叠。 |
| **通过标准** | 低频区域在首屏不可见 (已折叠)；中频区域的折叠状态有记忆或合理的默认值；折叠/展开按钮文案清晰 (如 "代理设置" 而非 "展开")。 |
| **常见修复动作** | 将低频面板统一使用 fold-card 模式；为 fold-card 设计默认展开/折叠策略；在多个 fold-card 时提供"全部展开/折叠"快捷操作。 |

### 维度 E: 长页面可达性 (Long-Page Reachability)

| 项目 | 内容 |
|------|------|
| **观察对象** | 超过 2 屏的页面: 控制台 (目录区)、书库总览 (卡片网格)、单本详情 (多 section)、阅读器 (正文)、设置页 (5 个 fold-card)。 |
| **采集方式** | 记录页面的逻辑区块数；检查是否存在区块间跳转能力 (锚点/FAB/目录)；检查滚动后是否能快速回到顶部或关键操作区。 |
| **通过标准** | 超过 3 个逻辑区块的页面应提供区块间导航；超过 5 屏的页面应有回到顶部入口；长列表页面应提供搜索/过滤来减少滚动。 |
| **常见修复动作** | 添加悬浮 FAB 承载回到顶部/到底部/区块锚点；为详情页各 section 设置 scroll-margin-top 和 id；在目录区添加锚点跳转。 |

### 维度 F: 文案用户视角 (UX Copy)

| 项目 | 内容 |
|------|------|
| **观察对象** | 所有面向用户的文本: 标题、副文案、按钮文本、placeholder、空状态、通知消息、label、tooltip。 |
| **采集方式** | 逐页提取所有用户可见文本。标注: 是否包含技术术语 (如 "SSE" "SQLite" "Promise")；是否解释了操作后果；空状态是否说明了"为什么空"和"该怎么办"。 |
| **通过标准** | 零技术黑话；每个按钮文本能独立表达操作含义 (不用依赖上下文)；空状态文案遵循 "当前状态 + 原因 + 下一步操作" 三段式；通知文案遵循 "发生了什么 + 接下来能做什么"。 |
| **常见修复动作** | 将技术术语替换为用户视角描述 (如 "SSE 流" → "实时进度推送")；为空状态补充引导性文案；统一按钮命名规范 (动词+对象)。 |

### 维度 G: 响应式与触控 (Responsive & Touch)

| 项目 | 内容 |
|------|------|
| **观察对象** | 900px、720px 断点下的布局变化；所有可交互元素的最小触摸目标；横屏/竖屏切换。 |
| **采集方式** | 在 Chrome DevTools 设备模拟中切换 900px 和 720px 宽度。检查: 按钮是否仍然 ≥ 44px 高度；文字是否溢出或截断；导航是否可完整访问；折叠/展开是否仍可用。 |
| **通过标准** | 所有交互元素 ≥ 44px × 44px 触摸目标；无水平滚动；文字不截断 (允许省略号)；主导航在窄屏下仍可完整操作。 |
| **常见修复动作** | 窄屏下导航改为横向滚动或折叠菜单；增大窄屏下的按钮 padding；确保 toast 不遮挡导航。 |

### 维度 H: 键盘焦点与无障碍 (Keyboard & A11y)

| 项目 | 内容 |
|------|------|
| **观察对象** | Tab 键焦点顺序；焦点可见性 (focus-visible)；模态/抽屉的焦点陷阱；aria 属性完整性。 |
| **采集方式** | 纯键盘走查: Tab 遍历所有交互元素，记录焦点顺序和可见性；在抽屉/弹层打开时检查焦点是否被困在内部；检查关闭操作是否可用 Escape 键。 |
| **通过标准** | 焦点顺序符合视觉顺序；所有交互元素有可见焦点指示；模态/抽屉打开时焦点移入、关闭时焦点回归触发元素；Escape 可关闭弹层。 |
| **常见修复动作** | 为缺少 focus-visible 样式的元素补充 outline；为抽屉添加焦点陷阱；确保 skip-link 或键盘可达的区块导航存在。 |

## 2. 证据采集格式

每条扫描记录统一使用以下格式:

```markdown
### [页面] - [区块] - [元素]

- **维度**: A-H 之一
- **问题类型**: 层级不清 / 权重失衡 / 空间浪费 / 缺折叠 / 难到达 / 文案偏技术 / 响应式问题 / 键盘问题
- **现状描述**: 客观描述当前表现
- **影响范围**: 单页 / 全局模式 / 多页
- **建议修复**: 具体可执行的动作 (不是方向性建议)
- **优先级**: P0 (阻断) / P1 (高) / P2 (中) / P3 (低)
```

**优先级定义**:
- **P0**: 导致用户无法完成核心任务 (如按钮不可点击、导航不可达)
- **P1**: 显著降低效率或造成困惑 (如主操作不明显、长页面无导航)
- **P2**: 影响体验一致性或美观 (如间距不统一、次要信息占主视觉位)
- **P3**: 锦上添花 (如动画缺失、微调间距)

## 3. 扫描执行顺序 (Phase 1 / Step 3)

按以下顺序逐页扫描，每页完成后再进入下一页:

1. **全局壳层** (`AppShell`): 先扫导航、页头、摘要卡片、通知 — 这是所有页面的公共基线。
2. **控制台** (`ControlConsole`): 高频操作页面，表单 + 目录 + sticky dock 的交互链路。
3. **监控页** (`MonitorDashboard`): 信息展示为主，检查实时数据可读性和历史记录导航。
4. **设置页** (`SystemPreferences`): 折叠卡片模式的参考实现，检查折叠策略和表单体验。
5. **书库总览** (`LibraryWorkspace` view=page): 卡片网格 + 搜索 + 语法提示的交互。
6. **单本详情** (`LibraryWorkspace` view=detail): 多 section 长页面，别名/书签/导出/目录各区。
7. **阅读器** (`LibraryWorkspace` view=reader): 长文本阅读 + FAB + 抽屉 + 排版面板。

**扫描纪律**:
- 每页先完整截图 (桌面 + 平板 + 移动宽度)，再逐维度记录。
- 只记录证据，不在扫描阶段修改代码。
- 同一页面内发现的问题归并后再进入下一页。
- 全局性问题 (如按钮权重规范不统一) 标记为 "全局模式" 影响范围。

## 4. 重构执行顺序 (Phase 2+3)

扫描完成后，重构按以下顺序执行，确保每一次提交都是可验收的独立增量:

### 第一批: 全局壳层 + 视觉规范 (Phase 2 Step 4+5)
1. `styles.css`: 扩展间距/层级/按钮/折叠规范 (CSS 变量 + 工具类)
2. `app-shell.tsx`: 导航吸顶化 + 头压缩 + 摘要密度调整
3. `App.tsx`: 适配壳层变更

### 第二批: 低复杂度页面 (Phase 2 Step 6a)
4. `monitor-dashboard.tsx` + `status-panel.tsx` + `task-monitor.tsx`: 视觉层级和空间利用率
5. `system-preferences.tsx`: 折叠全部/展开全部 + fold-card 规范落地
6. `control-console.tsx` + `metadata-board.tsx`: 表单层级和操作权重

### 第三批: 书库 + 长页面 (Phase 2 Step 6b + Phase 3)
7. `library-workspace.tsx` 总览视图: 卡片网格和搜索体验
8. `library-workspace.tsx` 详情视图: 多 section 长页面 + FAB 悬浮导航
9. `library-workspace.tsx` 阅读器视图: FAB 功能扩展 + 锚点

### 第四批: 文案 + 反馈 (Phase 3 Step 8)
10. 逐页清理文案和通知

### 验收
11. `npm run test:web` → `npm run typecheck` → `npm run build` → 手工走查矩阵
