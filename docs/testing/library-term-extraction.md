# 书库术语候选与 AI 提取验收

验收日期：2026-09-22。

## 使用流程

1. 在书籍详情的翻译面板打开「管理术语表」。
2. 可设置本书术语提取模型并保存；未指定时使用全局翻译偏好中的术语提取模型，再回退默认对话模型。
3. 点击「AI 提取候选」。后台按 18,000 字符窗口扫描已下载章节，浮窗显示已完成批次、识别候选数和本次新增数。关闭页面不取消任务；需要停止时点击「取消提取」。
4. 按待确认状态筛选，检查来源与 AI 说明，单条或批量确认/排除。列表每页显示 50 条，「全选当前筛选」覆盖所有匹配页。
5. 为确认的术语填写译法并启动翻译。仍有候选未确认时显示数量提醒，翻译正常启动。

手工添加默认已确认；AI 提取和图谱导入新增的术语为待确认。旧数据库中的存量术语迁移为已确认。待确认和已排除条目均不注入粗翻上下文，也不计入缺译统计。精翻创建仅复制已确认的书库术语，之后仍使用独立的精翻候选确认流程。

重复扫描按源词去重，保留已有确认、排除与人工编辑结果。每批候选和进度在一个 SQLite 事务中保存；取消或失败保留已完成批次。重启时残留运行任务标记失败，可重新提取补齐。

## 自动化验收

以下检查全部通过：

- `npm run typecheck`
- `npm run build`（Vite 仍提示主包体积超过 500 kB）
- `npm run test:server`：190 个测试通过。
- `npm run test:web`：59 个测试通过。

新增测试位于 `src/server/core/library-term-extraction.test.ts` 和 `src/server/routes/library-terms.test.ts`。覆盖状态筛选与批量更新、旧库迁移、跨窗口来源、路由优先级、缺译过滤、幂等去重、取消后的晚到响应、重启恢复、失败后重跑及 API 校验。生命周期测试使用内存 SQLite 与假模型；旧库迁移另用临时数据库模拟旧表。翻译注入测试通过本地假模型 HTTP 端点捕获实际提示词，验证只出现已确认术语，并核对精翻快照过滤结果。

使用独立临时数据库复制书库中 `syosetu/n3130lr` 的「01 曇りの聖女」章节（2,052 字符），配合现有模型配置进行浏览器操作验收：

- AI 扫描完成 1/1 批，识别并新增 24 条待确认候选，条目展示来源章节与提取说明。
- 在浮窗中批量确认人名「カーマイン・マロット」和称号「曇りの聖女」，待确认数量变为 22，缺译仅计入这两条确认术语。
- 按已确认筛选后，为人名保存译法「卡迈因·马洛特」，缺译数量变为 1。
- 发起翻译时显示「22 条候选尚未确认」，仍正常启动；真实模型完成元数据与正文两个单元，失败数为 0。
- 窄屏下检查浮窗排版、候选状态、模型入口和进度显示。
- 另补充 35 条临时候选验证分页：共 59 条、待确认 57 条时，跨两页全选并批量排除 57 条，待确认归零且已确认术语保持不变。
